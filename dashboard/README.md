# dashboard

검수용 로컬 대시보드. 문장 하나를 실행하면 처리 단계가 순서대로 보이고, 차량 그림에서 무엇이 바뀌었는지
확인하며, 발견한 문제를 그 자리에서 파일로 남긴다.

실행과 채점은 `eval/run_eval.py`의 `run_case`, `eval/score.py`의 `score_record`를 그대로 부른다.
그래서 화면 결과와 명령줄(`run_eval.py`, `score.py`) 결과가 같다.

## 실행

```bash
uv sync --extra dashboard --extra cloud     # 처음 한 번. 로컬 모델이면 cloud 대신 local
make dashboard                              # http://localhost:8000
```

- 모델은 `.env`의 `LLM_PROVIDER`, `LLM_MODEL`로 시작한다. 화면 위쪽 모델 칸에 `openai:gpt-4o-mini`, `ollama:qwen3:4b`
  형식으로 적고 "적용"을 누르면 바뀐다
- 키가 없거나 패키지가 없으면 서버는 뜨고, 모델 칸 옆에 사유가 나온다
- 인터넷 없이도 화면은 뜬다 (외부 글꼴·스크립트를 쓰지 않는다)

## 검수 주간 사용 순서

1. 오른쪽 위 "검수자"에 이름을 적는다. 기록 파일 이름이 된다 (브라우저에 저장됨)
2. "평가" 탭에서 유형·도메인을 고르고 "전체 실행". 표에서 "실패만 보기"로 틀린 건을 추린다
3. 표의 줄을 누르면 왼쪽 차량과 "흐름" 탭에 그 건이 다시 나온다. 어느 단계에서 갈렸는지 단계를 눌러 본다
4. 아래 버튼으로 남긴다: 정답이 이상하면 "정답 기준 이의", 모델·코드가 틀렸으면 "코드·프롬프트 문제". 메모 한 줄을 같이 적는다
5. "실행" 탭에서 평가셋에 없는 말을 직접 넣어 본다. 넣을 만하면 "평가셋 추가 후보"로 기록하고
   "평가셋 형식으로 내보내기"로 초안을 만든다

## 화면

- **왼쪽 차량**: 실행 전에는 시작 상태, 실행 후에는 결과. 바뀐 부위는 파랑(이전값 → 새값), 거절은 빨강과 사유,
  되묻기는 노랑 말풍선. 아래에서 시작 속도와 전원을 바꾸면 그 값이 건의 `state`로 들어간다
- **실행**: 자유 입력은 대화로 이어진다. 한 번 실행한 뒤 또 입력하면 앞의 발화까지 묶어 여러 턴(`turns`)으로 다시 실행한다.
  "새 대화"로 끊는다. 평가셋 목록에서 건을 고르면 발화와 시작 상태가 채워진다. 발화나 시작 상태를 고치면 자유 입력으로 실행된다
- **흐름**: 그래프의 실제 노드 `tool_select → validate → execute → respond`. 건너뛴 단계는 흐리게 나온다
- **평가**: 정답과 실제, 도구·인자·상태 세 가지 판정. 자유 입력은 정답이 없어 채점하지 않는다
- 응답 시간은 화면으로 진행을 보내는 시간이 포함돼 있어 "참고용"이다. 수치는 `eval/run_eval.py`로 잰다

## 기록 파일

`eval/review/` 아래에 사람별로 쌓인다. 여러 명이 동시에 올려도 충돌하지 않게 파일을 나눴다. **커밋 대상이다.**

| 파일 | 내용 |
|------|------|
| `findings_<이름>.jsonl` | 검수 기록 한 줄씩. 분류, 메모, 발화, 시작 상태, 정답, 실제, trace, 응답 문장, 모델, 시각 |
| `candidates_<이름>.jsonl` | 평가셋 형식 초안. `expected`와 `type`은 실제 동작에서 채운 값이라 사람이 고쳐야 한다 |

초안을 평가셋에 넣을 때는 `draft` 필드를 지우고 `id`를 정한 뒤 `eval/data/`의 파일로 옮기고 `make validate-eval`을 돌린다.

## 구조

| 파일 | 역할 |
|------|------|
| `server.py` | FastAPI. 그래프를 쥔 작업자 하나가 요청을 한 건씩 처리한다 (시뮬레이터 상태가 섞이지 않게) |
| `index.html` | 화면 전체. 파일 하나, 빌드 없음 |

차량의 부위는 상태 키(VSS 경로)의 패턴으로 정한다(`index.html`의 `RULES`). 같은 패턴의 신호가 늘면 자동으로 그려지고,
어느 패턴에도 안 맞는 키는 "주행" 목록에 그대로 나온다. `agent/`, `tools/`, `eval/`은 이 폴더를 import하지 않는다.
