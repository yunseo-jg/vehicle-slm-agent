# 설계 결정 기록

되돌리기 어려운 결정을 날짜와 이유와 함께 남긴다. 회의록은 노션, 여기는 코드에 영향 주는 것만.

| 날짜 | 결정 | 이유 | 대안 |
|------|------|------|------|
| 2026-09-05 | 도메인: 차량. 온디바이스 SLM tool-calling | 오프라인 필요성, 기능이 명확, 응답 속도가 평가 기준이 됨 | |
| 2026-09-09 | 엣지 보드 없이 노트북에서 네트워크 차단 실행 | 팀에 보드 경험자 없음. 에이전트 본질에서 멀어짐 | Jetson, 라즈베리파이 |
| 2026-09-09 | 온톨로지(YAML) → 스키마·시뮬레이터 자동 생성 | 도메인 교체 가능성, 도구 정의 단일화 | 코드에 직접 정의 |
| 2026-09-09 | 기능 목록 기준은 COVESA VSS 6.0 | 지어내지 않은 근거. 상태 키 이름 통일 | 자체 정의 |
| 2026-09-09 | rdflib/VSSo 안 씀. YAML로 시작 | 관계 표현이 필요해지면 그때 전환 | |
| 2026-09-09 | 도구 반환 형식 `{status, code, state_after}` | 채점 편의 | 문자열 반환 |
| 2026-11-14 | 에이전트 그래프는 4노드: tool_select → validate → execute → respond | 모델 호출은 턴당 1회. 의도 파악 노드를 따로 두지 않고 도구 선택이 겸한다 | intent 노드 분리 |
| 2026-11-14 | 검증은 코드가 한다. validate 노드가 tools.json 만으로 required·enum·범위·precondition 을 검사 | 모델은 도구와 인자를 고르기만 한다. 안전을 모델 판단에 맡기지 않는다 | 모델이 스스로 거절 |
| 2026-11-14 | 되묻기·거절 문장은 고정. 되묻기는 `vehicle.yaml`의 `ask_prompt`, 거절은 에러 코드별 문장 | 응답에 모델을 다시 부르지 않아 빠르고, 같은 상황에 같은 문장이 나와 채점이 흔들리지 않는다 | 모델이 응답 문장 생성 |
| 2026-11-14 | 채점은 실행된 도구 기준. `trace`에 선택(`selected_tool`)·실행(`executed_tool`)·결과(`outcome`, `code`)를 따로 기록 | 모델이 도구를 맞게 골랐는데 코드가 막은 경우와 처음부터 못 고른 경우를 구분할 수 있다. `unsafe`·`blocked` 정답 `tool: null`은 실행된 도구가 없다는 뜻 | 모델이 고른 도구 기준 |
